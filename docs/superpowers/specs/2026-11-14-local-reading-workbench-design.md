# 小说产物本地工作台：设计草案

日期：2026-11-14。状态：用户已于当前对话回复“继续吧”确认设计，进入实现计划阶段。

## 目的与已确认决策

让用户在浏览器中浏览 chinese-novelist 已有的创作产物，替代逐个打开 Markdown 和 JSON 文件。入口仍然是 Coding Agent 或 Personal Agent 触发 skill；可在已有项目上单独启动工作台。

用户已确认：

- 第一版聚焦已有产物的只读可视化，支持同一工作区的多部小说。
- 使用随文件变化更新的本地服务，不采用定期生成的静态阅读站。
- 整体视觉采用“阅读书房”，组件采用“细线书页”。参照当前聊天中的 reading-room-components.html 原型。
- 本轮不做审阅待办、编辑、Agent 通信、启动/暂停创作、改稿、导出或发布。这些不属于第一版的实现和验收范围。

先前讨论过的协作规则仅作为未来约束：开工前允许审查准备资料；连续创作期间不打断 Agent，意见只进入待办；本轮写作和自动校验结束后才开放改稿。当前版本不实现这些能力。

## 方案比较

### 静态阅读站

扫描文件并生成可分享的静态站。无需常驻进程，但源文件更新后需重新生成。用户没有选择这一方向。

### 本地只读工作台（用户选择）

Node.js 本地服务读取指定工作区，浏览器展示书架与作品资料。源文件变化后自动更新，不额外维护作品数据库。

下面的具体工程选型是设计提案，不代表用户已逐项确认。

## 技术提案

- 服务端使用 Node.js 与标准库，不调用模型 API，不引入数据库。
- 前端采用 HTML、CSS、原生 JavaScript 模块。当前仓库没有前端工程；首版内容以文档浏览为主，不引入 React/Vue 和必须执行的前端构建步骤。
- Markdown 使用固定版本的解析与内容清理依赖，所需运行资产随 skill 打包；具体库、版本和许可核查在实现计划中确定。浏览器运行时不依赖 CDN，不要求用户联网安装组件。
- 工作台脚本和静态资产随 skill 安装，读取小说的路径由启动参数指定；不将网站代码复制进每部小说目录。
- 启动方式拟为 `node <skillBaseDir>/scripts/workbench.mjs --workspace <小说集合目录>`，输出本地访问地址。支持可选端口；默认尝试可用端口。仅监听 127.0.0.1。
- 浏览器第一次连接读取作品列表及文档；服务端用 SSE 通知源数据版本变化。监测层采用有节流的定期扫描，避免依赖跨平台递归 watch 的行为。页面断线后重连并核对版本，提供手动重试入口。
- 不提供文件写入接口。浏览器的阅读设置和上次阅读位置只存于浏览器本地，不改变小说文件。

## 启动与作品发现

`--workspace` 指定的是作品集合目录：其直接子目录是小说项目。也允许参数直接指向一部小说目录。是否为项目，通过写作计划、编号资料文档、章节文件等组合证据判断，不要求所有文件齐全；仅有任意普通 Markdown 的目录不能直接算作小说。

skill 集成时将当前工作目录下的 `chinese-novelist/` 作为默认作品集合路径，显式传给服务。目录不存在时展示空状态，不扫描用户全盘。排除 user-preferences.json、隐藏目录和服务自身资源；不递归收集项目内部的备份目录。

扫描支持没有写作计划的旧作品：使用目录名和现存文档识别，缺失字段显示“未记录”。同名作品用来源目录区分；路由使用稳定项目标识，不能只用书名。

首次打开默认进入“全部作品”。从 Agent 为某部小说打开页面时，可使用该作品的深链接直接进入。浏览器前进后退、刷新和复制当前页面地址保留项目、资料类型、章节选择。

## 页面与交互

### 工作区书架

以安静的书目列表展示所有作品，不依赖封面图片。

每部作品展示书名、已有题材、记录的章节完成数/计划总章数、记录字数与文件最近更新时间。不存在的信息省略或标明未记录，不由模型补写。字数来自现有写作计划，明确为“计划记录字数”，不冒充重新校验值。

点击作品进入详情。书架自动发现新增/删除的项目，并保留当前浏览位置。当前作品被删除时显示说明和返回书架入口。

### 作品空间

顶部为产品名称、可展开书目的当前书名、返回全部作品入口。资料导航使用文字和细线选中态，不采用填色胶囊。深层章节目录与阅读排版工具按需展开，避免常驻多栏压缩正文。

作品资料包括：

| 页面 | 数据来源 | 展示方式 |
| --- | --- | --- |
| 大纲 | 01-大纲.md | 原文标题层级、章节规划表、全书悬念；支持章节锚点 |
| 人物 | 00-人物档案.md | 原文按角色标题形成阅读目录；保留已有字段 |
| 设定词典 | 大纲中的设定词典或设定与事实词典 | 提取对应标题下内容；明确包含完整真相、可能剧透 |
| 文风 | 03-文风基准.md | 文风指纹、基准段落、校准段落等原始内容 |
| 摘要 | 99-章节摘要.md | 按章节标题导航；旧作品可读取大纲内章节摘要区 |
| 章节进度 | 02-写作计划.json | 逐章显示原始记录状态、字数及通过标记；同时区分文件存在性 |
| 正文 | 章节 Markdown | 章节目录、上一章/下一章、正文排版与原文件视图 |

章节进度是安静的列表，不使用虚构评分、校验结论或管理驾驶舱。`completed` 显示为“计划标记已完成”，不能推断作者审定或全部校验通过。若状态与文件不一致，直接展示“记录已完成，正文文件缺失”等提示，不修改记录。

资料缺失时该入口保留，显示具体缺失资料和返回入口。无法可靠分节时降级为完整 Markdown，不丢掉内容、不伪造结构化字段。大纲包含完整真相，默认属于作者查看场景；词典页提示剧透即可，不新增权限模式。

### 正文阅读

- 纸张暖色背景、衬线正文、适度行长与留白；随系统外观提供深色配色。
- 默认隐藏模板的本章概要、章节备注，只展示标题、章首引子与正文。可切换“原文件”查看全部渲染内容。
- 按 Markdown 标题层级识别标准模板边界，不能靠任意字符串包含来截断。非标准章节无法确定边界时显示完整文档，并说明当前为完整文档视图。
- 章节按数字章号排序，优先遵循写作计划映射；实际存在但不在计划中的章节也可浏览，标为未列入计划；没有文件的计划项不能当成可读正文。
- 目录、字体大小、行距、上一章/下一章均可操作。章节位置按作品分别保存。
- 原型中的示例正文不会进入正式产品。产品只展示文件内容，不补写简介、人物动机或摘要。

## 文件更新与阅读稳定性

页面刷新数据不能把用户强制带回书架、跳到最新章或重置正在阅读的章节。

- 非当前文档变化：自动更新目录、状态与其他数据，保持当前正文位置。
- 当前正文/资料发生变化：显示“此文档已更新，点击载入”，用户决定何时重载，避免 Agent 写入时页面不断跳动。未打开的文档下一次进入时读取最新版本。
- 部分写入、暂时无效的 JSON 或短暂文件替换：短暂合并变化并重试，保留最近一次可读数据，明确提示读取异常/旧数据；没有旧数据时显示错误与重试，不将错误变成零章或完稿。
- 阅读长篇时一次加载一份文档，书架只读取必要元数据；章节正文按需读取。删除、新增和改名在重新扫描后反映。

## 只读与兼容边界

- URL 使用项目/文档标识映射，服务端验证读取路径位于指定工作区的实际路径内；不允许通过路径穿越或符号链接读到外部文件。
- Markdown HTML、链接与图片按本地文档渲染边界处理：清理脚本、事件属性和危险 URL；不执行文档中的代码。原始文件视图仍为安全渲染，不执行内嵌 HTML。
- 不自动加载远程图片；工作区内资源通过受限资源映射展示，越界或不可读的资源给出占位提示。链接不用于读取任意本地路径。
- 工作台不迁移、重写或修复任何小说文件，不依赖写入目标工作区才能启动。
- 保持 Node 环境要求与现有 skill 声明一致；若实现需要提高最低版本，必须在实现前另行说明原因，不能静默升级要求。

## 技术与视觉的验收范围

1. 从指定目录发现多部小说，能进入、切换、返回；同名作品能区分。
2. 展示所有现有类型产物；缺文件、旧摘要布局、无计划、损坏 JSON 有明确降级。
3. 正文中模板元数据不会混入默认阅读稿；原文件模式仍能查看全部内容。
4. 文件变化后更新书架和非当前文档；当前文档提示重载，保持阅读位置。
5. 前端导航、作品深链接、浏览器返回与刷新行为一致。
6. 暖纸色、细线文字导航、平面书目、衬线正文符合已选方向；窄屏可阅读，无重叠溢出；键盘可操作。
7. 不存在写入、编辑、待办、Agent 通信与创作控制入口。
8. 验证仅在指定目录内读取、安全渲染 Markdown，以及运行时离线可用。

## 交付与留给实现者的决定

交付服务启动脚本、前端资产、数据读取/解析模块、必要测试，以及 README 和 skill 流程中的启动说明。集成应说明服务与 Agent 独立：关闭 Agent 不等于服务必定仍存活；服务停止时页面提示重启命令。

具体目录命名、内部模块划分、端口分配策略、扫描间隔与节流参数、解析库版本、SSE 消息结构、测试工具由实现计划选定。无需为这些细节再次逐项询问用户；不得以此扩展本版功能范围。
