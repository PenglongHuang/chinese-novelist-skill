# 章节摘要框架与模板精简

用户已确认：规划时按全部章节预建摘要框架，写前读取已有摘要，写后 Edit 原小节；空框架不计有效摘要，并行仍遵守冲突检测/批次汇总协议。

## Approach

采用独立 Markdown 摘要模板，沿用原文件和状态脚本。相比只在流程中描述格式，实际框架可直接定位、编辑和验收；无需引入第二份 JSON 摘要或新状态。

## Contract

- `99-章节摘要.md` 在规划阶段按计划章号顺序预建全部章节：二级标题 `第{XX}章 {标题}`，三级标题“关键事件与后果”“人物当前处境”“行动条件与未了事项”。XX 至少两位，计划 JSON 的数值章号与标题为准。
- 初始字段留空，不杜撰前情；空标题、注释和待填写提示不算有效摘要。结构化摘要的“关键事件与后果”必须有实际内容；其余字段可简写无新增或引用此前章号。旧版非空叙述摘要继续可读。
- 串行修改已有小节；批次文件采用同一格式。汇总时填入对应空小节，保留其他章节、标题和非章节说明，不追加同章空/实两个副本、不覆盖已有有效摘要。
- 阅读时只承接有内容的摘要；空壳/冲突则回查正文。未完成不得提交 completed。
- 精简大纲、人物、正文模板及摘要流程的重复指导，保留关键字段、格式锚点与写作约束；人物反派可选，字数使用本书约定，摘要编写规则集中到新模板。

## Validation

解析、目录覆盖率和完成门槛测试覆盖空框架、占位符、已填写与旧摘要、人物栏单独填写、批次填入空壳、原文保留。Node 16/24 和 Chrome 验证兼容；独立 Agent 前后探针验证规划与 Edit 指令。无需改写既有小说数据。
