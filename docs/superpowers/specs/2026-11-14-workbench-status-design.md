# 工作台状态与真实产物一致性改进

用户确认：章节按 pending → in_progress → validating → completed 推进；失败进入 failed，修复可重新进入 in_progress。completed 必须有达标正文、正式摘要和已保存记录。项目最终有未解决问题时使用 needs_attention，不能统一标 completed。

本轮其余要求直接来自用户：状态筛选和颜色、实际字数、摘要可见、第二种主题、手动打开本地工作区。保留当前 chinese-novelist 产物目录名，支持显式选择包括 .chinese-novelist 在内的目录，不迁移现有作品。

实现决定：
- 实际字数与摘要覆盖从文件检查，按版本缓存；与计划状态不一致时显示“状态待同步”，不由浏览器写回或假定完成。
- 正式摘要优先，未合并的批次/旧大纲摘要可预览并显示来源；缺章和冲突显式提示。
- Node CLI 为唯一推荐状态写入口，锁定后重读计划、原子写回、严格验证完成门槛；并行 Agent 各章都调用，批次结果只在收尾核对，避免共享 JSON 覆写。
- CLI 对旧项目提供保守 reconcile：备份元数据，汇总已有摘要，填入实测字数；未明确完成的章节留在 validating，不把旧正文直接标完成。
- 主题使用“细线书页 / 清爽白纸”；浅/深/跟随系统另外选择，浏览器记忆。
- 顶部“打开工作区”支持粘贴目录绝对路径与最近目录。浏览器不能可靠给本地服务返回系统文件夹绝对路径，因此首版采用明确路径表单，非上传小说文件。配置切换通过同源 JSON POST，必须带会话 CSRF token，内容读取仍限定在用户选定根目录。打开新根成功后才替换现有根，错误不丢当前数据。
- 使用 Node16 和原生前端，运行时离线。当前 service 5112 仅在验证后重启到新代码。全局安装按会话已有同步授权更新并保留备份。

验收：使用临时目录先复现 pending+正文、batch摘要未汇总、完成缺摘要、切根失败等；真实工作区只读验收，并在备份后修复计数/摘要落盘，不改正文。浏览器验证筛选计数、两主题/三外观持久化、切根、目录、状态与摘要来源。
