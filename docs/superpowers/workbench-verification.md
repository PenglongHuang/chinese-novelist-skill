## 独立代码审查及修复

初次审查 507d415..58dd3b0 发现三项重要问题：代码围栏关闭判断可能截断正文、短暂文件替换绕过缓存、无效章节链接误用首章。修复前新增复现测试，修复后回归通过。

中文图片 URL 编码问题也已复现并修正。原报告将其列为小项，但中文文件名是本产品的正常输入，因此按重要可用性问题处理。安全路径限制仍生效。

## 实施判断与范围

- 添加局部 package.json 的 type:module，只用于让浏览器纯模块也可在 Node16 测试，不增加运行时安装步骤。
- 中文插图按正常输入修正编码匹配；否则合法本地插图会不可见。
- 对上游依赖使用官方归档及文件摘要验证，没有自行审计压缩库内部实现；上游缺陷仍需要后续依赖维护。
- 界面由实际截图和 Chrome 交互验证，未验证其他浏览器和系统字体组合的表现。

## 延后的小项

本仓库 Windows core.autocrlf 可能在全新检出时改变第三方 JS 的换行，导致文件字节 SHA256 与 THIRD_PARTY.md 中的上游 LF 摘要不同，不影响运行。后续可用明确的 vendor 换行属性固定供应资产字节；当前未改仓库 Git 属性。

## 启动

在此分支目录运行：

```bash
node scripts/workbench.mjs --workspace "小说集合目录或单部小说目录"
```

打开打印的本地 URL。指定 --port 可在重启后复用地址；Ctrl+C 停止服务。源目录没有作品时显示空书架，产品不会自动生成演示小说。
